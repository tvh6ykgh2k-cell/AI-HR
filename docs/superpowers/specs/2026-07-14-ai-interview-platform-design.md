# AI 面试官平台 — 设计规格说明书

**日期：** 2026-07-15（更新）
**状态：** Draft
**目标：** 构建一个本地运行的 AI 面试网站，Agnes AI 扮演面试官角色，支持截图识别 JD、语音输入、STAR 面试准备、自动保存到 Obsidian。
**参考技能：** [interview-prep-generator](https://github.com/paramchoudhary/resumeskills) — STAR 故事框架、面试题库、角色分析

---

## 1. 项目概述

### 1.1 核心价值

**双模式平台：**

- **🎙️ 模拟面试** — 粘贴 BOSS直聘 JD → AI 面试官实战 → 语音/文字交互 → 实时保存 Obsidian
- **📝 面试准备** — JD + 简历 → 生成 STAR 故事库 + 预测问题 + 自我介绍脚本 → 带着准备进入模拟面试

### 1.2 关键决策汇总

| 决策点 | 结论 |
|--------|------|
| 面试形式 | 文字为主 + 可选语音输入（混合模式） |
| 岗位输入 | 截图识别 JD（Agnes AI Vision），可手动编辑 |
| 面试节奏 | AI 主导式，面试官控场 |
| 面试官人格 | 自然语言描述 + 多维滑块调参 |
| 前端技术栈 | React 18 + TypeScript + Vite + Tailwind CSS + Framer Motion |
| 状态管理 | Zustand |
| 后端技术栈 | Hono（Node.js 轻量框架） |
| API 格式 | OpenAI 兼容（POST `https://apihub.agnes-ai.com/v1/chat/completions`） |
| Obsidian 路径 | `C:\Users\Administrator\Documents\Obsidian Vault\PM 面试` |
| 保存策略 | 每题实时追加保存 + 面试结束后生成完整总结版 |
| 部署模式 | 纯本地运行（`npm run dev`），后续再考虑部署 |
| API Key 管理 | `.env.local` 默认值 + 网页设置页可覆盖 |
| 面试准备 | STAR 故事银行 + 角色能力分析 + 问题预测 + 自我介绍脚本 |
| 面试评分 | 实时 STAR 结构评估（S/T/A/R 四要素完整性） |
| 复盘输出 | 准备文档 + 面试记录 + 每题 STAR 评分 + 改进建议 一体化 Markdown |

## 4. 面试官人格系统

### 4.1 自然语言描述

用户自由输入的人格描述直接作为 System Prompt 的一部分注入。例如：

> "你是一个腾讯 T9 级别的资深前端面试官，风格犀利但公正。你会深入追问候选人提到的每个技术点至少两层深度，但不会故意刁难。在候选人卡住时，你会给予适当的引导..."

### 4.2 风格滑块转译

| 滑块 | 范围 | 转译规则 |
|------|------|----------|
| 追问深度 | 浅 → 深 | 低="只问一层，回答后即进入下一题"；高="对每个技术回答至少追问2-3层深度" |
| 提问节奏 | 慢 → 快 | 低="给候选人充足的思考时间"；高="快速抛出下一个问题，保持高压节奏" |
| 严格程度 | 温和 → 严格 | 低="鼓励为主，委婉指出问题"；高="直接指出错误，给出不及格评价" |
| 提示频率 | 少 → 多 | 低="仅在候选人明确表示不会时才提示"；高="察觉到候选人犹豫时主动引导" |
| 技术深度 | 基础 → 底层 | 低="聚焦实际项目经验"；高="追问源码级实现和底层原理" |

### 4.3 System Prompt 组装

```
最终 System Prompt = 
  人格描述原文
  + 滑块转译指令
  + 岗位 JD 内容
  + 面试固定指令（"你是面试官，请根据以上JD对候选人进行面试。自然地开始，先让候选人做自我介绍..."）
```

### 4B.2 角色能力分析

从 JD 中提取面试官将考察的核心能力维度：

| 字段 | 说明 | 示例 |
|------|------|------|
| name | 能力名称 | "React 原理深度" |
| evidence | JD 证据 | "JD 要求 '精通 React 原理，理解 Fiber 机制'" |
| weight | 权重 | 高 / 中 / 低 |
| questionCount | 预计题数 | 4-6 题 |

### 4B.3 预测问题生成

基于 interview-prep-generator 的题型分类框架：

| 题型类别 | 示例 | 占比 |
|----------|------|------|
| **高概率·技术深挖** | "React Fiber 相比 Stack Reconciler 改进了什么？" | 35% |
| **高概率·项目经验** | "说说你做过的性能优化项目，用 STAR 方式回答" | 25% |
| **中概率·行为题** | "讲一次你带领团队攻克技术难点的经历" | 20% |
| **中概率·系统设计** | "设计一个支持百万级数据的表格组件" | 15% |
| **低概率·开放题** | "如果让你重新设计 React，你会改哪里？" | 5% |

R: 首屏 3.2s → 1.3s（↓59%），移动端留存率 +12%，

## 5. 对话数据流

### 5.1 一次 Q&A 的完整链路

```
前端                         后端                         Agnes AI
 │                            │                            │
 │  POST /api/chat            │                            │
 │  {sessionId, message}      │                            │
 │  ──────────────────────▶   │                            │
 │                            │  读取 settings.json         │
 │                            │  读取 session .md 历史      │
 │                            │  组装 System Prompt         │
 │                            │  组装 messages[]            │
 │                            │                            │
 │                            │  POST /v1/chat/completions │
 │                            │  {stream: true}            │
 │                            │  ───────────────────────▶  │
 │                            │                            │
 │                            │  ◀── SSE tokens ────────── │
 │                            │                            │
 │  ◀── SSE tokens ────────── │  同时追加写入 .md           │
 │                            │                            │
 │  data: [DONE]              │                            │
 │  ◀────────────────────     │                            │
 │                            │                            │
```

### 5.2 API 端点设计

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/chat` | POST | 发送消息，返回 SSE 流式响应 |
| `/api/chat/continue` | POST | 从历史面试继续（加载之前的 context） |
| `/api/recognize-jd` | POST | 上传截图 base64，返回结构化 JD |
| `/api/prep/generate` | POST | 生成面试准备文档（JD + 简历 → STAR 故事 + 问题预测） |
| `/api/prep/score-star` | POST | 对单个回答进行 STAR 结构评分 |
| `/api/sessions` | GET | 列出所有面试记录（含准备文档） |
| `/api/sessions/:id` | GET | 获取单次面试完整记录 |
| `/api/sessions/:id` | DELETE | 删除面试记录 |
| `/api/settings` | GET | 读取当前设置（人格、滑块、Key、路径） |
| `/api/settings` | PUT | 更新设置 |
| `/api/test-connection` | POST | 测试 Agnes AI 连接是否正常 |

### 5.3 上下文管理

- Agnes AI 上下文有限，后端实现滑动窗口：
  - System Prompt（始终保留）
  - 最近 N 轮完整 Q&A（N 可配置，默认 20 轮）
  - 当前用户消息
  - 超过窗口的早期对话从 API 请求中移除，但已保存在 Obsidian .md 中不丢失

### 5.4 流式传输格式

SSE（Server-Sent Events），每个 token 一个事件：

```
data: {"token": "说"}
data: {"token": "到"}
data: {"token": "React"}
...
data: [DONE]
```

前端使用 EventSource 或 fetch + ReadableStream 消费。
